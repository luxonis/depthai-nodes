01 / Input contract

Three views. One metric scene.

The candidate consumes a decoded Scene and a supplied plane. Upstream depth generation and file decoding are separate operations.

Geometry

XYZ in millimeters

Finite, read-only float32[N, 3] with an explicit common frame. No organized-grid assumption. Returned segments index the original XYZ rows.

Frozen computation samples rows at stride up to 64, reducing the stride to retain at least 16,384 points when available. Plot downsampling is separate.

Reference

Supplied upward plane

normal · XYZ + offset_mm = 0. Unit normal and offset in the same frame as the cloud. The camera is above the support surface.

This implementation does not estimate the plane. The app's calibration workflow is upstream.

Unrectified source pixels. Each view provides its delivered-grid intrinsics, distortion model/coefficients and scene-to-camera transform.

OAK application: synchronized color, mono, NeuralDepth LARGE 768×480 depth and organized PointCloud. The controller retains finite, nonzero XYZ in the common calibrated reference. The parcel wrappers check source timestamps within 10 ms and decode NV12 color to RGB.

02 / Algorithm walkthrough

Keep the geometry. Change the scheduling.

The seven-stage canvas is schematic. The two following examples use actual validation inputs and frozen execution traces.

Schematic · not a measured prediction

Three projection workers. Serial candidate checks.

Each view is projected once. Candidate visibility then runs sequentially. Contiguous depth-probe coordinate planes avoid the N×K×2 tensor and transpose. Probe positions, thresholds, membership and measurement rules are unchanged.

The app retains one newest native group while busy, decodes it when admitted, and submits it immediately after completion. One scene stays in flight.

find_candidates(scene):
  sample rows, preserving original indices
  project the three views with three workers
  threshold → voxelize → cluster → prepare grids
  validate each candidate sequentially
  join every worker before returning

measure(parcel, plane):
  unchanged supported footprint + height rules

Native archive replay

The untouched 4K holistic archive was also replayed through the final package, paced at 3 source frames/s to avoid source/ISP drift. It returned 663 successful batches and exit 0. In the final three-object timestamp interval, 21/25 outputs had three eligible objects, three had four and one had two. Field-count stability needs further work.

Measured population and scope

The processing FPS test repeatedly uses four recorded frames with three objects and fresh inference, not cached predictions. A new live three-object camera confirmation was not performed. Eighteen validation Scenes do not establish accuracy on unseen environments.
