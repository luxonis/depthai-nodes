Support plane calibration

Find and assess a surface under a fixed camera. The application uses human approval to decide which plane to activate and when to resume plane-dependent processing.

From camera setup to an active plane

  1. 01 · Application

    Wait for approval

    No saved plane. Keep acquisition running and send START.

  2. 02 · Calibration node

    Fit and assess

    Emit one batch per fit. Continue until at least one plane passes, or until STOP.

  3. 03 · Human review

    Choose a surface

    Review equations and evidence. Request a fresh check when needed.

  4. 04 · Application

    Activate and save

    Save the approved equation and enable plane-dependent processing.

The reviewer can decline the entire batch. The application can send START again immediately.

What each fitting attempt emits

Zero or more assessed equations from one cloud. The batch includes rejected fits and their reasons. A passing assessment ends the search and leaves approval to the application.

What verification measures

One supplied equation against the latest usable inputs. Evaluate rows and columns 0, 4, 8, … of the original organized cloud and keep points with z > 0. Low coverage can occur when objects cover the conveyor.

Public API

SupportPlaneCalibration.build(pointCloud, imu, pointCloudSize, config=None) links the sensor outputs. The node consumes inputs continuously. Fitting attempts start at least 0.5 seconds apart by default, and attempt_interval_sec is configurable.

PortMessage and behavior
pointCloud · inOrganized dai.PointCloudData in millimeters. Size is (width, height).
imu · indai.IMUData with acceleration in the point cloud’s coordinate frame.
inputControl · inSupportPlaneCalibrationControl.start() or .stop(). Another START can follow success or cancellation directly.
inputVerification · inSupportPlaneVerificationRequest(plane, request_id=None). Assess once, independently of search state.
candidatesOutput · outSupportPlaneCandidateBatch.assessments. One batch per completed fit. The search waits for fresh input between fits and keeps going if every fit is rejected.
verificationOutput · outSupportPlaneVerificationResult.assessment and the echoed request_id.
ConfigurationDefault and meaning
attempt_interval_sec0.5 seconds between fit starts.
max_gravity_angle_deg6.5 degrees maximum tilt from horizontal.
check_distance_mm30.0 mm maximum perpendicular distance for an on-plane point.
min_sampled_point_count500 valid grid samples to judge coverage.
min_on_plane_ratio0.10 minimum fraction of valid samples on the plane.
vertical_distance_range_mmNone. An installation can supply an inclusive distance range.

Shared PlaneAssessment

Equation, sampled point count, on-plane count and ratio, tilt, perpendicular distance, vertical distance, accepted, and structured failure reasons. Both paths use the same evaluator.

Source snapshot

Each result preserves the cloud’s sequence number and host, device, and optional system timestamps. It also records the gravity direction used and the IMU sample time when available.

Application-owned SupportPlaneStore

save(record), load(device_id=…, frame_id=…), and invalidate() manage versioned JSON. A stored record binds the equation to a device, frame, and approval time.

Storage defaults

An explicit path takes precedence. Standalone OAK apps use $OAKAGENT_STORAGE_APP/support-plane.json. Peripheral apps use the host’s per-user state directory, scoped by app and installation.

Python usage examples

Supply the camera setup, review UI, and application processing.

Wire the node and start a search

The application can show every batch while waiting for the first passing assessment.

from depthai_nodes.message import (
    SupportPlaneCalibrationControl,
    SupportPlaneVerificationRequest,
)
from depthai_nodes.node import SupportPlaneCalibration, SupportPlaneCalibrationConfig

cal = pipeline.create(SupportPlaneCalibration).build(
    pointCloud=cloud_out,
    imu=imu_out,
    pointCloudSize=(width, height),
    config=SupportPlaneCalibrationConfig(attempt_interval_sec=0.5),
)
control = cal.inputControl.createInputQueue()
batches = cal.candidatesOutput.createOutputQueue(blocking=True)
verify = cal.inputVerification.createInputQueue()
checks = cal.verificationOutput.createOutputQueue(blocking=True)

pipeline.start()
control.send(SupportPlaneCalibrationControl.start())
while True:
    batch = batches.get()
    show_assessments(batch.assessments)
    if any(result.accepted for result in batch.assessments):
        break  # Search ended. Human review is handled by the application.

Check a selected equation on demand

Use the reply to decide whether to approve the plane. Other requests can be matched by ID.

verify.send(SupportPlaneVerificationRequest(
    plane=selected_plane,
    request_id="review-42",
))
reply = checks.get()  # This example has one pending request.
show_assessment(reply.assessment)

# To cancel an active search:
control.send(SupportPlaneCalibrationControl.stop())

Save approval and load it after restart

After a movement event, clear the stored approval, pause dependent processing, and commission the installation again.

from datetime import datetime, timezone
from depthai_nodes import ActiveSupportPlane, SupportPlaneStore, resolve_support_plane_path

store = SupportPlaneStore(resolve_support_plane_path(
    app_id="conveyor-inspection", installation_id="line-4",
))

# After human approval:
store.save(ActiveSupportPlane(
    plane=approved_plane,
    device_id=device_id,
    frame_id=frame_id,
    approved_at=datetime.now(timezone.utc),
))

# On startup, apply the application's resume policy to this record.
saved = store.load(device_id=device_id, frame_id=frame_id)

# When the application invalidates approval:
store.invalidate()
